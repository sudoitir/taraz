# 0015. Entity تخت با JPA Embeddable

**وضعیت:** پذیرفته‌شده
**تاریخ:** ۲۰۲۶-۰۸-۱۸

## زمینه

مدل persistence نباید گراف عمیق شی‌گرا شود: relationهای JPA تو‌در‌تو (fetch زنجیره‌ای، lazy loading پنهان) رفتار query را غیرقابل‌پیش‌بینی می‌کند و زیر فشار هم‌زمانی (ADR-0026) به قفل و انتظار غیرضروری منجر می‌شود. مدل دامنه (ADR-0005) هم نباید گروگان annotationهای ORM باشد.

## تصمیم

Entityهای persistence **تخت** هستند و ترکیب از طریق `@Embeddable` / `@Embedded` انجام می‌شود؛ مدل دامنه جدا از مدل persistence باقی می‌ماند و mapping صریح در driven adapter انجام می‌شود (ADR-0006).

## گزینه‌های بررسی‌شده

- **Entityهای ORM به‌عنوان مدل دامنه** — رد شد: دامنه به framework آلوده می‌شود و قاعده‌ی «وابستگی صفر دامنه» (ADR-0005/0006) می‌شکند.
- **گراف relation عمیق (`@OneToMany` و …)** — رد شد: fetch strategy پنهان، N+1، و دایره‌ی قفل بزرگ‌تر از نیاز واقعی دامنه‌ی تک‌موجودی.

## پیامدها

### مثبت

- schema خوانا و queryها پیش‌بینی‌پذیر؛ قفل سطری دقیقاً روی همان سطری است که باید (ADR-0026).

### منفی / بدهی فنی

- mapping صریح دامنه ↔ persistence کد اضافه‌ای است که باید نگه داشته و تست شود؛ برای هر aggregate یک mapper.
