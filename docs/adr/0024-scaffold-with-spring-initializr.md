# 0024. اسکفولد با Spring Initializr و ساختار دستی

**وضعیت:** پذیرفته‌شده (جایگزین [0001](./0001-scaffold-with-jhipster.md))
**تاریخ:** ۲۰۲۶-۰۸-۱۸

## زمینه

پروژه به نقطه‌ی شروع استاندارد Spring Boot نیاز دارد. JHipster (ADR-0001) برای این کار انتخاب شده بود، اما ژنراتور آن معمولاً از نسخه‌های bleeding-edge مثل Spring Boot 4.1.0 عقب است و خروجی‌اش — که برای اپلیکیشن full-stack عمومی طراحی شده — پر از بخش‌هایی است که باید با معماری صریح (ADR-0006) تطبیق و حذف شوند؛ یعنی هزینه‌ی تطبیق از هزینه‌ی ساخت دستی بیشتر می‌شود.

## تصمیم

اسکفولد با **Spring Initializr** (bootstrapping مینیمال) و سپس **ساختاردهی دستی** دقیقاً طبق نقشه‌ی ADR-0006 (`core/`، `adapters/`، `container/`، `architecture-tests/`) انجام می‌شود. هیچ کدی وارد پروژه نمی‌شود مگر آن‌که جایش در معماری مشخص باشد.

## گزینه‌های بررسی‌شده

- **JHipster (تصمیم قبلی)** — منسوخ: عقب‌بودن از Boot 4.1 و خروجی prune-سنگین؛ ابزار general-purpose برای یک دامنه‌ی بسیار مشخص.
- **Initializr خام بدون بازسازی ساختار** — رد شد: ساختار پیش‌فرض لایه‌ای (controller/service/repository) با معماری صریح ناسازگار است.

## پیامدها

### مثبت

- هر فایل از روز اول جای درست خود را در معماری دارد؛ چیزی برای حذف‌کردن وجود ندارد.

### منفی / بدهی فنی

- سرعت شروع کمتر از ژنراتور؛ ساختار اولیه با دست ساخته می‌شود (که با تست‌های ArchUnit — ADR-0023 — از همان ابتدا قفل می‌شود).
