# 0036. Money با BigDecimal (واحد minor، تک‌ارزی ضمنی)

**وضعیت:** پذیرفته‌شده

**تاریخ:** ۲۰۲۶-۰۸-۱۸

## زمینه

امضای قرارداد چالش `long amount` است؛ یعنی مبلغ در مرز API به‌صورت واحد کوچک (minor units) صحیح می‌آید. سوال این است که نمایش داخلی پول در دامنه چه باشد. گزینه‌ی اول `long` بود، اما دو ضعف دارد: سقف `Long.MAX_VALUE` موجودی را محدود می‌کند و overflow باید با `Math.addExact` شکار و به خطای دامنه تبدیل شود — یعنی یک failure mode که اصلاً معنای کسب‌وکاری ندارد، فقط محدودیت نوع‌داده است. تصمیم‌گیرنده‌ی محصول (صاحب چالش) BigDecimal را ترجیح داد.

## تصمیم

- `Money` یک `record` با یک فیلد `BigDecimal` است؛ یک ارز ضمنی واحد در کل سیستم فرض می‌شود و فیلد currency وجود ندارد.
- مقادیر همیشه در واحد minor و **صحیح** نگه داشته می‌شوند: سازنده مقدار را normalize می‌کند (`stripTrailingZeros`) و factoryها مقدار کسری را با `INVALID_AMOUNT` رد می‌کنند — چون مرز API فقط `long` عرضه می‌کند و کسر در واحد minor معنا ندارد.
- موجودی‌ها هرگز منفی نمی‌شوند: `Money.of` فقط مقادیر `>= 0` و `Money.operationAmount` فقط مقادیر `> 0` را قبول می‌کند.
- overflow وجود ندارد: `BigDecimal.add` دقیق و بدون سقف است؛ کد خطای `BALANCE_OVERFLOW` از کاتالوگ حذف می‌شود. تنها failure mode حساب، منفی شدن در `minus` است که با `INSUFFICIENT_FUNDS` برمی‌گردد.
- مرز API همان `long` چالش می‌ماند؛ تبدیل `long → BigDecimal` در لبه‌ی ورودی (application layer) انجام می‌شود و دامنه فقط `Money` می‌بیند.
- برابری `Money` به‌لطف normalize کردن در سازنده، scale-blind است (`1.0` و `1.00` برابرند).

## گزینه‌های بررسی‌شده

- **`long` با `Math.addExact`** — رد شد (به نفع این تصمیم): سقف `Long.MAX_VALUE` و failure mode مصنوعی overflow؛ کافی است یک سیستم واقعی موجودی تجمیعی بزرگ‌تر از آن سقف داشته باشد.
- **`Money(amount, currency)`** — رد شد: هیچ‌جای API چالش currency عرضه نمی‌شود؛ فیلدی که همیشه خالی است فقط سطح invalid state را بزرگ می‌کند.
- **`long` خام بدون wrapper** — رد شد: قواعد دامنه (مثبت بودن مبلغ عملیات، صحیح بودن) باید یک جای متمرکز زندگی کنند، نه پراکنده در همه‌ی call siteها.

## پیامدها

### مثبت

- هیچ سقف مصنوعی برای موجودی نیست؛ overflow wrap بی‌صدا به مقدار منفی غیرممکن می‌شود (حذف یک کلاس کامل از باگ)؛ failure modeهای Money دقیقاً همان‌هایی هستند که معنای کسب‌وکاری دارند.

### منفی / بدهی فنی

- allocation بیشتر از `long` در hot path و مقایسه‌ی کندتر؛ با حجم این چالش ناچیز است. normalize اجباری در سازنده برای برابری scale-blind یک قرارداد است که باید در تست قفل شود. multi-currency همچنان پشتیبانی نمی‌شود.
