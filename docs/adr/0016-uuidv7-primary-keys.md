# 0016. کلید اصلی UUID v7 با B-tree index

**وضعیت:** پذیرفته‌شده
**تاریخ:** ۲۰۲۶-۰۸-۱۸

## زمینه

کلید اصلی جدول‌ها (حساب، تراکنش، outbox) باید بدون round-trip به دیتابیس تولید شود و الگوی درج را خراب نکند. UUID v4 تصادفی، درج‌ها را در سراسر B-tree پخش می‌کند (page split، fragmentation)؛ sequence هم تولید ID را به دیتابیس گره می‌زند و در محیط distributed سخت می‌شود.

## تصمیم

کلید اصلی همه‌ی جدول‌ها **UUID v7** (مرتب‌شونده بر اساس زمان، RFC 9562) با **B-tree index** است؛ تولید ID سمت اپلیکیشن.

## گزینه‌های بررسی‌شده

- **UUID v4** — رد شد: درج تصادفی در B-tree یعنی page split مداوم و cache locality بد.
- **BIGSERIAL / sequence** — رد شد: تولید ID نیازمند round-trip یا allocation مرکزی؛ با scale-out و تولید ID در اپلیکیشن ناسازگار.
- **ULID / Snowflake** — رد شد: UUID v7 استاندارد رسمی است و در Postgres و کتابخانه‌های Java پوشش بهتری دارد.

## پیامدها

### مثبت

- درج‌ها تقریباً به انتهای index می‌روند (page locality بهتر)؛ تولید ID سمت اپلیکیشن و بدون round-trip؛ مرتب‌سازی زمانی تقریبی رایگان.

### منفی / بدهی فنی

- ۱۶ بایت به‌جای ۸ بایت bigint؛ نیازمند کتابخانه‌ی تولید UUID v7 در Java (تا پشتیبانی بومی JDK).
