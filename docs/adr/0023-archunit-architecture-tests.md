# 0023. تست قوانین معماری با ArchUnit

**وضعیت:** پذیرفته‌شده
**تاریخ:** ۲۰۲۶-۰۸-۱۸

## زمینه

قاعده‌ی سختِ معماری صریح (ADR-0006) — «driving adapter outbound port را نبیند، دامنه وابستگی صفر به framework داشته باشد» — اگر فقط مستند یا قرارداد شفاهی باشد، در review فرسوده می‌شود و به‌تدریج شکسته خواهد شد.

## تصمیم

دایرکتوری/ماژول اختصاصی **`architecture-tests/`** بدون هیچ کد production؛ فقط تست‌های **ArchUnit** که bytecode همه‌ی ماژول‌ها را import می‌کنند و قوانین مرزی را assert می‌کنند:

- driving adapters → فقط inbound port و read-side port؛ وابستگی به outbound port **ممنوع**.
- domain → وابستگی صفر به framework و adapter، در هر دو جهت.
- application/service → فقط outbound portها، نه پیاده‌سازی‌های driven.
- driven adapters → هرگز به driving adapter یا container وابسته نیستند.
- قراردادهای نام‌گذاری لایه‌ها.

این تست‌ها سازوکار واقعی enforce هستند، نه مستندِ قصد.

## گزینه‌های بررسی‌شده

- **بازبینی دستی در code review** — رد شد: تحت فشار زمان فرسوده می‌شود.
- **قوانین فقط در مستندات** — رد شد: مستند enforce نمی‌کند.

## پیامدها

### مثبت

- شکستن مرز لایه‌ها = قرمزشدن build؛ قوانین با `./mvnw test` در هرم تست اجرا می‌شوند.

### منفی / بدهی فنی

- هزینه‌ی نگهداشت قوانین هنگام تغییر ساختار بسته‌ها؛ تست‌های معماری باید با refactor ساختاری به‌روز شوند.
