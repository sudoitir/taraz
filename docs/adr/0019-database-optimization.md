# 0019. انضباط بهینه‌سازی PostgreSQL

**وضعیت:** پذیرفته‌شده
**تاریخ:** ۲۰۲۶-۰۸-۱۸

## زمینه

عملکرد دیتابیس از روز اول یک تصمیم طراحی است، نه بهینه‌سازی بعد از بحران. زیر بار هم‌زمانی چالش، چیدمان بد ستون‌ها (alignment padding)، index نادرست و autovacuum تنظیم‌نشده روی جداول داغ (account، outbox) خودش را به‌صورت contention و latency نشان می‌دهد.

## تصمیم

انضباط‌های Postgres در همه‌ی migrationها (ADR-0014) اعمال و در review بررسی می‌شود:

- **نوع و اندازه‌ی درست ستون‌ها** — بدون `text` بی‌دلیل، بدون `numeric` برای مبالغ صحیح.
- **مرتب‌سازی ستون‌ها** — fixed-width (مانند `uuid`، `bigint`، `timestamptz`) اول، variable-width آخر، برای کمینه‌کردن alignment padding.
- **تنظیم autovacuum** متناسب با جدول داغ outbox (churn بالای insert/update).
- **Index آگاهانه** — هر index یک پرس‌وجوی واقعی را سرو می‌کند؛ index تزئینی ممنوع.

## گزینه‌های بررسی‌شده

- **بهینه‌سازی وقتی مشکل دیدیم** — رد شد: در داده‌ی مالی، «بعداً» یعنی بعد از incident؛ هزینه‌ی انضباط از روز اول ناچیز است.
- **تنظیمات پیش‌فرض Postgres** — رد شد: پیش‌فرض‌ها برای چالش مصرفی‌اند؛ جدول outbox با churn بالا نیازمند تنظیم صریح است.

## پیامدها

### مثبت

- رفتار دیتابیس زیر بار قابل‌پیش‌بینی؛ schema در review قابل‌داوری با معیارهای مشخص.

### منفی / بدهی فنی

- هر migration سربار بررسی دارد؛ دانش لازم در تیم باید نگه داشته شود.
