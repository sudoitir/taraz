# 0025. زیرساخت توسعه با docker-compose (بدون Dev Container)

**وضعیت:** پذیرفته‌شده (جایگزین [0003](./0003-dev-container.md))
**تاریخ:** ۲۰۲۶-۰۸-۱۸

## زمینه

زیرساخت‌های اجرایی (PostgreSQL، Valkey، Kafka) باید با یک دستور و به‌شکل بازتولیدپذیر بالا بیایند. Dev Container (ADR-0003) کل محیط توسعه (JDK، ابزارها) را هم containerize می‌کرد، اما هزینه‌ی نگهداشت `.devcontainer` و افت کارایی روی macOS (فایل‌سیستم shared) از فایده‌اش برای این پروژه بیشتر است — مخصوصاً که Testcontainers در تست‌ها (ADR-0022) خودش infra را مدیریت می‌کند.

## تصمیم

فقط **docker-compose** برای سرویس‌های زیرساخت (PostgreSQL، Valkey، Kafka) تعریف می‌شود؛ JDK و Maven روی میزبان نصب‌اند. دستور بالاآوردن از طریق justfile (ADR-0004) یکدست می‌ماند.

## گزینه‌های بررسی‌شده

- **Dev Container (تصمیم قبلی)** — منسوخ: نگهداشت سنگین و کندی روی macOS؛ Testcontainers نیاز «infra در تست» را پوشش می‌دهد.
- **نصب دستی سرویس‌ها روی میزبان** — رد شد: نسخه‌ها drift می‌گیرند و محیط بازتولیدپذیر نیست.

## پیامدها

### مثبت

- یک فایل compose ساده؛ شروع سریع‌تر؛ شکاف کمتر بین dev و CI (که خود با containers کار می‌کند).

### منفی / بدهی فنی

- توسعه‌دهنده باید JDK 21 و Maven را روی میزبان داشته باشد؛ نسخه‌ی toolchain به‌جای container با Maven wrapper و مستندات پین می‌شود.
